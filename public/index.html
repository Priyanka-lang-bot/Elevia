A wrong answer is a symptom, not a diagnosis

Students often follow a rule that looks right to them. Marking it wrong, or re-teaching the whole chapter, doesn't find that rule. Teaching to a guess can waste time or reinforce the wrong idea.

1

Marks say what, not why

"2/5" is wrong, but the score doesn't show the student added the tops and the bottoms separately.

2

One mistake can be a slip

A single wrong answer might just be a typo or a rushed moment. Treating every slip as a gap wastes the student's time.

3

The real gap is often earlier

Trouble adding fractions can come from an earlier skill, like finding common denominators.

How ELEVIA works

Four coordinated roles move each student through one learning journey. Every decision is made by fixed, testable rules, so the same answers always lead to the same outcome.

  1. 1

    Diagnoser

    Reads the check-in answers and matches wrong answers against known misconception patterns. A single mistake is flagged as a possible slip.

    Suggests a possible gap
  2. 2

    Checker

    Asks 2 brand-new questions. Same mistake again: confirmed. All correct: rejected. Mixed: inconclusive, so a teacher decides.

    Verifies before teaching
  3. 3

    Planner

    Plans only for a confirmed gap. Walks the skill map's prerequisites to pick where to start.

    Chooses the focus
  4. 4

    Tutor

    Explains the missing step with worked examples and practice questions with hints. Maths in examples is computed exactly.

    Teaches the missing step
  5. ↻

    Retest

    After a delay, 3 new questions. 2 out of 3 closes the gap and marks the skill mastered. Otherwise ELEVIA replans with a fresh lesson.

    Checks it stuck

Optional AI can rewrite a lesson's wording. Its output is checked, and if it fails the original template text is used. It never makes the decisions above.

What's built

Everything below works in the current version and is covered by automated tests.

  • 🔍

    Misconception detection

    82 named misconception patterns across 24 topics, each tied to the skill it points to.

  • ✓

    Verify before you teach

    No lesson is planned for a gap that hasn't been confirmed by new questions or a teacher.

  • 🗺

    Plans from a skill map

    Prerequisites decide where a learning plan starts.

  • 📘

    Step-by-step lessons

    Worked examples, sense checks, practice with hints and full solutions.

  • ⏱

    Delayed retests

    Retests use new questions after a gap (24 h by default), never a repeat of the check-in.

  • 📈

    Progress you can trust

    Only a passed retest marks a skill mastered. Progress is saved after every answer.

  • 🧑‍🏫

    Teacher review

    Teachers resolve unclear cases, change the focus, and every decision is logged with a reason.

  • 🔒

    Consent and privacy

    Parent consent for under-18s, school codes, and adult learners choose exactly what to share.

  • ≡

    Exact answer checking

    Exact fraction arithmetic, accepted-answer lists, and code answers verified by running the snippets when the question bank is built.

Verify before you teach

ELEVIA's core rule: a suspected misconception is a hypothesis until new evidence supports it.

The usual way

  1. Wrong answer
  2. Assume the cause
  3. Re-teach
  4. Hope it worked

The ELEVIA way

  1. Wrong answer matches a known pattern
  2. Suspected gap: nothing changes yet
  3. 2 new questions: confirmed, rejected or inconclusive
  4. Lesson only for a confirmed gap
  5. Retest on new questions later

About ELEVIA

ELEVIA is being built for PRASUNEX Innovathon 2026, around one question: how do we close the actual gap in a student's understanding instead of just marking answers? It is a working prototype. It hasn't been tested in classrooms yet, so we make no claims about learning outcomes.

What's next: more topics (reading comprehension, electricity, light, probability), wider prerequisite planning, and classroom pilots with teachers.
